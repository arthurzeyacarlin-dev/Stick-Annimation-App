## Core Rule

A successful compile is necessary but never sufficient. Every Spec Executor task must technically prove:

- the exact triggering flow
- the real execution path
- the expected state and visible result
- persistence/reload behavior when relevant
- all protected unrelated flows named in the active spec
- no browser/page errors and no warnings except an exact spec-reviewed, evidence-bound accepted-warning rule
- the exact checks that passed, failed, were skipped, or remain unproven

## Role-Separated Phase Proof

Technical proof and final project-state proof have different owners:

### Spec Executor technical proof

1. Work only in the dedicated phase worktree from the authorized canonical-main SHA.
2. Change only the phase-authorized implementation, fixture, and technical-test files; ignored proof artifacts are allowed.
3. Run the phase's deterministic, type, lint-baseline, browser, and regression commands as applicable.
4. Create and independently validate the technical `proof-manifest.json` and command receipts.
5. Record the exact base/HEAD, dirty-path allowlist, empty index, proof-manifest SHA, pass/fail/skipped/unproven matrix, and cleanup in the Implementation Review Packet.
6. Stop completely. Do not edit canonical control-plane files, run memory regeneration as a writer, finalize the tracked-state closeout, stage, commit, merge, push, or publish.

### Acceptance and ownership transfer

- Arthur and the Project Manager accept or reject the technical implementation.
- Rejection returns to a separately authorized Spec Executor correction task; no propagation or publication occurs.
- Acceptance permits transfer only after the executor is fully stopped. The Control Plane Architect then verifies the accepted base/branch, exact dirty paths, empty index, technical-manifest hash, clean proof-artifact inventory, and exclusive ownership before editing.
- The two roles never edit the same worktree concurrently.

### Control Plane Architect final proof

1. Preserve the accepted implementation/fixture/test bytes exactly. Any required correction returns to a Spec Executor.
2. Update the canonical spec, status, TODO, decisions when applicable, changelog, handoff, and generated project tree.
3. Run `bash scripts/update_memory.sh`, revalidate the existing technical manifest, and run the phase's tracked-state finalizer plus independent closeout validator.
4. Run `bash scripts/update_memory.sh --check-only`, both Git diff checks, the exact changed-path allowlist check, status/spec/handoff consistency checks, and final empty-index/untracked checks.
5. Return the Control Plane Architect PM Review Packet and stop.

Only a later explicit publication instruction authorizes the Control Plane Architect to stage, commit, integrate into canonical `main`, push, and verify. The finalizer therefore runs before staging while `HEAD` still equals the authorized phase base and the index is empty. Publication stages only the accepted implementation and reviewed control-plane paths, commits on the phase branch, fast-forwards a clean canonical `main`, pushes `origin/main`, and proves clean `0/0` synchronization. If canonical `main` advanced or any path differs from the reviewed packet, stop without pull, merge, rebase, force-push, history rewrite, or scope expansion.

SPEC-0001 Phase 1 used the previous combined process and remains the Verified/published/integrated historical exception; its proof is not regenerated by this decision.

### Decision-complete SPEC-0005 proof standard

SPEC-0005 has exactly seven sequential phases. Each gets one new Plan-mode Spec Executor/worktree, the phase's exact tracked-path ceiling, ignored output only under `output/spec-0005/phase-N/**`, an independently validated technical manifest, visible Arthur review where output exists, sequential CPA closeout after acceptance, and separate publication/integration before the next phase.

The shared full-playback definition is exact: after one Play action, automation observes ordered frame indexes `0, 1, …, last, 0`, performs no manual frame selection during that cycle, and records elapsed time within `75%..150%` of `frameCount / fps`. It records timestamped per-frame body geometry at desktop `1440×900` and compact `390×844`. Pause occurs only after wrap. Still screenshots and a Play/Pause state toggle are supporting evidence, never full-playback proof.

Quality evidence must use an independently authored accepted-reference catalog and independently authored bad-motion mutations whose hashes are bound before the engine runs. The implementation under test may not generate both the result and its sole oracle.
