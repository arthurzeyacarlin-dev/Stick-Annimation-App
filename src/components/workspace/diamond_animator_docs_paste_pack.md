# Diamond Animator Master Project

## Purpose of This File

This file is the top-level source of truth for the Diamond Animator application.
It exists so that developers, Codex, and future AI agents understand exactly what Diamond Animator is supposed to be, what Version 1 includes, what future systems are not part of Version 1, and what core product principles must never be violated.

This file should be read before changing architecture, UI, workflow, AI systems, or workspace behavior.

## What Diamond Animator Is

Diamond Animator is a professional animation platform designed to drastically reduce the time required to create high-quality animations.

It combines two creation environments inside one product:

1. Drawing Animation Workspace
2. Stick Figure Animation Workspace

The platform is built around speed, creative control, AI assistance, and clean workflow design.

Diamond Animator is not supposed to feel like a toy, a fake AI gimmick, or an overcomplicated experiment. It is supposed to feel like serious animation software that helps people create faster.

## Core Goal

The core goal of Diamond Animator is:

**Create animations faster without sacrificing quality or creative control.**

The app should save time for users by reducing repetitive work, helping organize workflow, and integrating AI in a useful way.

## Core Product Identity

Diamond Animator must feel:

- fast
- serious
- creative
- professional
- visually clean
- trustworthy
- helpful without being pushy

It must support both beginners and more serious creators.

## Version 1 Scope

Version 1 includes only the systems needed to establish the main app foundation.

### Version 1 includes

- Main screen / home screen
- New Project flow
- Drawing Animation Workspace
- Stick Figure Animation Workspace
- Open Project flow
- Learn / tutorial area
- AI Assistant guidance screen
- Export tool
- AI Project Assistance / AI Finalizer
- Add-ons placeholder / coming soon system
- Menu system
- Account / support structure
- Project viewing concepts
- Timeline system for both workspaces

### Version 1 does not include

- 3D animation mode
- 2D + 3D integrated animation mode
- giant AI upgrade packs
- AI agents that control third-party software
- advanced future-only add-on systems
- any future feature pack that belongs to later versions

Those future ideas are important, but they are not part of Version 1 build requirements.

## Main Screen Structure

The main screen is the user’s entry point into Diamond Animator Pro.

The visual layout contains:

- dark interface with subtle blue influence
- center divider line / main page structure
- top-right branded header
- menu button
- main action buttons
- tools section
- scrollable layout if content height requires it

### Header area

At the top-right header area, the UI includes:

- Diamond Animator Pro
- Diamond icon
- tagline under the title: **Create, Animate, Dominate**
- menu button at the far right

### Main action buttons

The main action buttons on the home screen are:

#### New Project
Description: Create a new project.

#### Open Project
Description: Open an existing project.

#### Learn
Description: Learn the app and animation.

#### AI Assistant
Description: Ask questions and get guidance.

### Tools section

The tools section on the home screen contains:

#### Export
Description: Export the animation.

#### AI Project Assistance
Description: Apply final AI touches to your project.

#### Add-ons
Description: Extend your workspace with new tools and upgrades.

## New Project Flow

When the user clicks **New Project**, they enter the project creation page.

This page includes:

- back button
- small label: New Project
- large heading: Create a New Project
- description: What would you like to create?
- divider line
- two large workspace selection buttons

### Project type buttons

1. Drawing Animation Workspace
2. Stick Figure Animation

Only these two project types matter for Version 1.

## Drawing Animation Workspace Summary

The Drawing Animation Workspace is the hand-drawn animation environment.

Its purpose is to let users create professional drawing-based animation with the help of AI.

It includes:

- central canvas
- drawing tools
- right-side panel system
- AI animator panel
- timeline
- playback controls
- asset/library support where needed

It should feel like serious drawing software, but faster and more guided.

## Stick Figure Animation Workspace Summary

The Stick Figure Animation Workspace is the stick animation environment.

Its purpose is to let users animate stick figures quickly and professionally.

Its design direction is a hybrid between:
- simple stick animation usability
- more advanced future-capable control

It includes:

- central canvas
- top project controls
- right-side stick figure tools
- AI animation help
- bottom timeline

It is not supposed to be a copy of the drawing workspace. It must have its own role and its own tool focus.

## Open Project System

Open Project is used to continue editing an existing project.

Projects are displayed as project cards.

Each card should show:

- project thumbnail
- project title
- project type
- drawing project or stick figure project label

Projects should be sorted from newest to oldest.

Users click a card to open the project in editing mode.

## My Projects Concept

My Projects is a project viewing concept for watching project results without entering edit mode.

Purpose:

- watch finished or in-progress projects
- preview personal animations
- separate viewing from editing

This is more like a project viewer than an editor.

## Learn System

The Learn section teaches users both:

- how to use the app
- animation fundamentals

It should primarily contain tutorial videos.

Example tutorial categories:

- app basics
- drawing workspace basics
- stick figure workspace basics
- animation fundamentals

Optional future enhancement:
- after a tutorial is watched, the user may receive an optional challenge exercise

Challenges should help users practice, but should not be mandatory.

## AI Assistant System

The AI Assistant exists to answer user questions and guide users to the right area of the app.

Its job is not only to answer questions, but also to help with navigation.

Examples:

- user asks how to export
- AI explains and offers to take them to Export

- user asks how to start stick figure animation
- AI explains and offers to take them to New Project > Stick Figure Animation

The assistant should feel like a built-in guide, not just a generic chat box.

## Export Tool

The Export tool allows a user to choose a project and export it.

Version 1 export should remain simple, professional, and understandable.

Expected flow:

1. choose project
2. choose export route or format
3. confirm export

Possible destinations or outputs may include:

- download
- video file
- email
- messaging/share outputs
- future integrations

## AI Project Assistance / Finalizer

AI Project Assistance is used after a project is mostly complete.

Purpose:

- smooth animation
- improve timing
- apply final polish
- improve impact moments
- perform helpful project finishing tasks

Important rule:
The original project must remain safe.

Finalization should ideally create a processed/finalized version, not destroy the original editable project.

## Add-ons System

Version 1 Add-ons is not a real feature marketplace yet.

In Version 1 it is only a placeholder / future notice area.

When opened, it should explain that:

- add-ons are not yet available
- the app is still in development
- future versions and upgrades may come later

It may include:
- close button
- don't show again option
- optional link to future updates or channel

## Menu System

The menu includes:

- About / Description
- Terms of Policy
- Support area
- Report Problem
- Account area
- Sign in
- Log in
- Sign out
- version display

The menu should be simple, professional, and easy to scan.

## UI Philosophy

Diamond Animator uses a dark visual language with a subtle blue influence.

Reason:
- dark interfaces feel serious and modern
- blue connects to the Diamond Animator identity
- the app should feel calm, clean, and high-value

The UI should not feel cluttered, childish, or cheap.

## Product Principles

Diamond Animator must follow these principles:

1. Speed matters
2. Clarity matters
3. Creative control matters
4. AI should assist, not replace
5. Trust must be protected
6. Version 1 should focus on foundation, not feature explosion

## Long-Term Direction

The long-term direction includes possible future systems such as:

- major AI upgrades
- 3D animation
- 2D + 3D integrated workflows
- AI agents interacting with external animation software

These are future ambitions, not Version 1 requirements.

# Timeline System

## Purpose

The timeline is the bottom animation control system used in both workspaces.

It controls the order, duration, and type of animation frames.

## Timeline Requirements

The timeline must support:

- frame selection
- keyframe insertion
- blank keyframe insertion
- tween frame insertion
- frame span stretching
- frame deletion
- playback stepping
- FPS controls

## Frame Types

Version 1 timeline uses these important ideas:

- frame
- keyframe
- blank keyframe
- tween frame

### Frame
Used to extend timing and hold a state.

### Keyframe
Used to create a new actual state.

### Blank Keyframe
Used to create a new blank state.

### Tween Frame
Used to create tween motion timing.

## Span Behavior

Frame and tween durations are represented as stretched spans, not as strange duplicated-looking artifacts.

Important rules:

- a span should read clearly as one continuous duration
- one span should have one start dot
- tween should visually read as tween immediately
- frame should visually read as frame immediately

## Timeline UX Principles

The timeline should feel:

- clear
- stable
- easy to read
- easy to stretch
- not cluttered
- professional

## Visual Identity

- gray for normal frame timing
- blue for tween timing
- black dot for true span start
- selected state should use clean blue outline

## Timeline Scaling

Timeline supports large frame counts and must remain readable.

It should support:
- ruler labels
- clear tick hierarchy
- large timeline range
- horizontal scrolling when needed

# Drawing Workspace

## Purpose

The Drawing Workspace is the professional hand-drawn animation environment of Diamond Animator.

It exists for creators who want to animate through drawing, frame editing, and AI-assisted drawing workflows.

## Main Goal

Give users a serious drawing animation experience similar in spirit to professional software, while making the process faster through AI support and cleaner workflow design.

## Core Regions

The Drawing Workspace contains four major regions:

1. Top bar
2. Central canvas
3. Right-side panel system
4. Timeline

## Top Bar

The top bar includes:

- project name / rename area
- save and project controls
- playback-related controls if needed
- general workspace command area

## Canvas

The canvas is the central working area.

Users should be able to:

- draw
- erase
- select
- edit frame content
- preview onion skin
- zoom and pan

The canvas must remain the largest visual region.

## Right-Side Panel System

The right side is split vertically.

### Top right
Used for properties, assets, library, and relevant drawing controls.

### Bottom right
Reserved for AI Animator.

The AI panel is important and should feel central and powerful, not like an afterthought.

## Timeline

The timeline sits at the bottom and drives frame control.

It must support professional frame editing behavior.

## Assets and Library

The drawing workspace may include asset and library support because drawing-based workflows often need reusable items and stored project resources.

## AI Assistance

The AI in this workspace should help with:

- frame generation
- cleanup
- rough-to-clean help
- animation speed support

The AI should accelerate work without replacing user control.

# Stick Figure Workspace

## Purpose

The Stick Figure Workspace is the stick-animation environment in Diamond Animator.

It exists for users who want to animate stick figures quickly and professionally.

## Design Direction

The design direction is a hybrid system:

- simple enough for easier stick animation entry
- strong enough to support more professional behavior later

## Core Regions

The Stick Figure Workspace contains:

1. Top bar
2. Central canvas
3. Right-side control system
4. Timeline

## Key Difference From Drawing Workspace

Unlike the Drawing Workspace, the Stick Figure Workspace is not built around drawing assets and drawing library systems.

Its tool system is focused on:

- stick figure creation
- stick figure editing
- stick figure movement
- pose control
- animation behavior
- AI help for motion

## Right Side

The right side is used for:

- stick figure tools
- figure editing controls
- AI assistance

The lower-right AI region remains important.

## Canvas

The canvas remains central and large.

It is used for stick pose editing and motion setup.

## Timeline

The timeline still controls:

- frame states
- keyframes
- blank frames where needed
- tween timing
- playback timing

## Version 1 Expectation

Version 1 should make this workspace feel like a serious stick animation environment, not a toy.
